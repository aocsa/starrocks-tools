# Piece 9 — C7 — future branch `stacked/cn-nixl-session-warmup` (on C6b)
Commit title: `fix(cn): pre-establish nixl peer sessions so a cold cluster cannot deadlock`

Plan references: golden-crane.md "The map" row C7, carve-sheet bullet **C7** (fold `SIRIUS_CN_NIXL_WARMUP`/`SIRIUS_CN_NIXL_WARMUP_PEERS` into the C4 registry instead of raw `env::var`); appendix lines 419–583 (FILES bullet for `nixl_transport/warmup.rs`, the `lib.rs` `list_alive_compute_nodes` bullet, LAYERS entry `stacked/cn-nixl-session-warmup`, the RISKS bullets about warmup tests behind the feature gate) and lines 2066–2068.

Why: CN A's transport thread blocks in an outbound `exchange_nixl_md` to B while B's thread blocks in its own outbound call to A; an all-to-all shuffle first-contacts every peer at once, so a cold cluster deadlocks. Reproduced 2026-08-08 on a 4-CN cluster: q14 run 1 cold FAILED after 121 s (errorCode=62, "method request time out 60000ms"), run 2 warm 751 ms. Establishing every directed peer session at bring-up, with `rpc_exchange_md` on the warmup thread, removes the deadlock.
