## 4. Model change verdict

None required. Every carrier above is an existing FSM state/attribute or a new *instance* of an existing resource type:
DataBatch (`constructed/stationary/in_transit/destructed`, `rust/crates/telemetry/model/src/data_batch.rs`), BatchPlacement (`origin: String`, `batch.rs:21-32`), Query/QueryGroup/Engine (`quent-query-engine-model`; `Engine.Init.implementation.custom_attributes` is `DynamicAttributes`), Operator `Statistics.custom_attributes` (`operator.rs:18-21`), stdlib `Memory`/`Channel` (declared at runtime in `memory_context.cpp`).
Decisions that *would* add entity types, left to the lead: (1) `IoRead` FSM for per-request I/O timelines; (2) `Fragment` FSM for CN-side pre-build/park states. If either is taken, the bridge regenerates automatically: `rust/crates/telemetry/bridge/build.rs` runs `quent_codegen::emit_cxx(instrumentation_model::SiriusModel::build("Sirius"))` at cargo build, driven by CMake Corrosion (`bridge/CMakeLists.txt`, headers copied to the gitignored `bridge/include/telemetry-bridge/gen/*.rs.h`), so `make release` picks up a model edit; Rust side `cargo test -p instrumentation-model -p sirius-telemetry-analyzer` (analyzer reads `Constructed.producer_pipeline_uuid`, `analyzer/src/data_batch.rs:32-37`, `model.rs:657-681`).
